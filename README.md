ダイビングサークルの共有魚図鑑。**閲覧は誰でも・投稿も誰でも(個人識別のみ・承認なし)**。

- 公開URL: https://hishisyu354-commits.github.io/zukan-lagoon/
- リポジトリ: https://github.com/hishisyu354-commits/zukan-lagoon (公開)

- **土台は案A** = GitHub Pages + GAS + スプレッドシート + Drive。LINEログインは使わない(将来B拡張可)
- **承認機能は一旦なし**(「一旦、承認機能はいらん」2026-08-22)。個人の識別だけ行い、まず菱沼+2人で回す
- 費用: ¥0 / クレカ不要 / LINE Developers設定も不要

## ユーザー識別(端末トークン方式・承認なし)

1. 各端末は初回投稿時に**秘密の乱数トークン**(192bit)を自動生成しlocalStorageに保存。書き込みに毎回添付
2. GASのmembersシートが トークン→(表示名・状態) を管理。状態は `owner / member / blocked`
3. **未知のトークンは即memberとして登録され、そのまま投稿できる**(承認フローなし)
4. 名前は投稿フォームの名前欄がそのまま自分の名前。同じトークン(=同じ端末)からなら変更できる
5. オーナーは `setup()` が発行する**オーナーコード**を `#/setup` に入力して確定。役割は「管理」タブでの**ブロック**(非常ブレーキ)のみ

割り切っている点(了承済みの前提):
- URLを知っていれば誰でも投稿できる(リポジトリ公開なのでURLは隠せない)。荒れたら①ブロック②シート直編集で削除③承認制の復活(サーバー数行で戻せる)の順で対処
- 名前は自己申告。3人の内輪運用では問題にならない前提
- 端末=人。ブラウザデータ削除・機種変でトークンが変わると別人扱い(名前を同じにすれば見た目は連続)

## 構成

```
閲覧者(誰でも) ──GET──> GASウェブアプリ ──> スプレッドシート(fish/records/comments/points/members)
投稿者(誰でも) ─POST─> 　同上(端末トークンで個人を識別・blockedのみ拒否)
写真 ──────────────────> Driveフォルダ(リンクを知っている人は閲覧可)
フロント: index.html 1枚(GitHub Pages)。CONFIG.GAS_URLが空の間はモックモード(localStorage)
```

削除・修正はスプレッドシート直編集で行う(削除APIを持たない=攻撃面を減らす)。

## ポイントと検索(2026-08-23更新)
- ポイントは**エリア > サブエリア > ポイント**の階層(例: 伊豆 > 大瀬崎 > 先端)。現在11ヶ所(底土を追加)
- **正本はフロントの `POINTS_MASTER`**(index.html内)。追加・修正はClaudeに言うかここを編集してpush(シート手修正・GAS再デプロイ不要)
- サーバーのpointsシートは「フロントに無い新しいid」の行を足した場合だけ追加ポイントとして合流する拡張口
- 検索は魚名に加えて**階層のどの地名でもヒット**する(「八丈島」→島内全ポイントの魚、「大瀬崎」→湾内+先端の魚)。マップの検索欄でも同様
- 緯度経度は**おおよそ**の目安値

## 写真の公平表示と編集(2026-08-23追加)
- 魚詳細のメイン写真は**全記録の写真を横スワイプで見るカルーセル**(撮影者名+日付のクレジット付き・新しい順)。「代表1枚」方式をやめ、複数人が同じ魚を投稿しても全員の写真が大きく出る
- **編集**: 魚の情報(名前/レア度/解説)は**メンバー全員が共同編集可**(表記ゆれ・レア度の合議を想定)。発見記録(ポイント/日付/水深/メモ/写真の追加・削除)は**投稿した本人+オーナーのみ**(トークンでサーバー側判定)。削除した写真はDriveのゴミ箱へ
- 記録の「編集」ボタンは表示名が自分と一致する記録に出す(見た目の判定。実際の権限はサーバーが強制)
- **サーバー更新が必要**: editFish/editRecord APIはCode.gsの貼り直し+「デプロイを管理→編集→新バージョン」で反映(URL不変)。未反映のまま編集を押すと「サーバー側の更新が必要です」と出る
