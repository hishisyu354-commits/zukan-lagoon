# 図鑑ラグーン (dive-zukan)

ダイビングサークルの共有魚図鑑。**閲覧は誰でも・投稿も誰でも(個人識別のみ・承認なし)**。

- 公開URL: https://hishisyu354-commits.github.io/zukan-lagoon/
- リポジトリ: https://github.com/hishisyu354-commits/zukan-lagoon (公開)

決定事項(2026-08-22 菱沼):
- 名前=図鑑ラグーン / UIは明るいラグーントーン / 下部タブ(図鑑・記録)
- **土台は案A** = GitHub Pages + GAS + スプレッドシート + Drive。LINEログインは使わない(将来B拡張可)
- **承認機能は一旦なし**(「一旦、承認機能はいらん」2026-08-22)。個人の識別だけ行い、まず菱沼+2人で回す
- 費用: ¥0 / クレカ不要 / LINE Developers設定も不要

## ユーザー識別(端末トークン方式・承認なし)

1. 各端末は初回投稿時に**秘密の乱数トークン**(192bit)を自動生成しlocalStorageに保存。書き込みに毎回添付
2. GASのmembersシートが トークン→(表示名・状態) を管理。状態は `owner / member / blocked`
3. **未知のトークンは即memberとして登録され、そのまま投稿できる**(承認フローなし)
4. 名前は投稿フォームの名前欄がそのまま自分の名前。同じトークン(=同じ端末)からなら変更できる
5. オーナーは `setup()` が発行する**オーナーコード**を `#/setup` に入力して確定。役割は「管理」タブでの**ブロック**(非常ブレーキ)のみ

割り切っている点(了承済みの前提):
- URLを知っていれば誰でも投稿できる(リポジトリ公開なのでURLは隠せない)。荒れたら①ブロック②シート直編集で削除③承認制の復活(サーバー数行で戻せる)の順で対処
- 名前は自己申告。3人の内輪運用では問題にならない前提
- 端末=人。ブラウザデータ削除・機種変でトークンが変わると別人扱い(名前を同じにすれば見た目は連続)

## 構成

```
閲覧者(誰でも) ──GET──> GASウェブアプリ ──> スプレッドシート(fish/records/comments/points/members)
投稿者(誰でも) ─POST─> 　同上(端末トークンで個人を識別・blockedのみ拒否)
写真 ──────────────────> Driveフォルダ(リンクを知っている人は閲覧可)
フロント: index.html 1枚(GitHub Pages)。CONFIG.GAS_URLが空の間はモックモード(localStorage)
```

削除・修正はスプレッドシート直編集で行う(削除APIを持たない=攻撃面を減らす)。

## ポイントと検索(2026-08-23更新)
- ポイントは**エリア > サブエリア > ポイント**の階層(例: 伊豆 > 大瀬崎 > 先端)。現在11ヶ所(底土を追加)
- **正本はフロントの `POINTS_MASTER`**(index.html内)。追加・修正はClaudeに言うかここを編集してpush(シート手修正・GAS再デプロイ不要)
- サーバーのpointsシートは「フロントに無い新しいid」の行を足した場合だけ追加ポイントとして合流する拡張口
- 検索は魚名に加えて**階層のどの地名でもヒット**する(「八丈島」→島内全ポイントの魚、「大瀬崎」→湾内+先端の魚)。マップの検索欄でも同様
- 緯度経度は**おおよそ**の目安値

## 写真の公平表示と編集(2026-08-23追加)
- 魚詳細のメイン写真は**全記録の写真を横スワイプで見るカルーセル**(撮影者名+日付のクレジット付き・新しい順)。「代表1枚」方式をやめ、複数人が同じ魚を投稿しても全員の写真が大きく出る
- **編集**: 魚の情報(名前/レア度/解説)は**メンバー全員が共同編集可**(表記ゆれ・レア度の合議を想定)。発見記録(ポイント/日付/水深/メモ/写真の追加・削除)は**投稿した本人+オーナーのみ**(トークンでサーバー側判定)。削除した写真はDriveのゴミ箱へ
- 記録の「編集」ボタンは表示名が自分と一致する記録に出す(見た目の判定。実際の権限はサーバーが強制)
- **見られるポイント(2026-08-23)**: 魚の編集画面で複数選択チップから追加(記録が無い場所も可)。「見られた場所」表示・ポイント絞り込み・エリア検索・マップの種数すべてに効く。fishシートにknownPointIds列(初回書き込み時に自動で列追加)
- **見られる季節(2026-08-23)**: 記録日付の分布は「年中いる魚が秋にしか見えない」誤解を生むため(菱沼指摘)、**宣言式の手動フィールド**に変更。春夏秋冬の複数選択・4つ全部=「年中」表示。記録分布は「記録のあった季節」として併記(証拠と宣言を分離)
- **ポイントの自由追加(2026-08-23)**: 投稿/記録編集フォームのポイント選択に「＋リストにないポイントを追加」。エリア(必須)/サブエリア(任意)/ポイント名(必須)を入れると即登録され、そのまま記録に使える。メンバーなら誰でも可。完全一致の重複は既存ポイントに合流。座標は空で登録される(マップに載せたい分はClaudeに言えばlat/lngを補う)
- **ピンチズーム固定(2026-08-23)**: ページ全体の拡大をviewport meta+touch-action+gestureイベント無効化の3層で禁止(iOSはmetaだけでは塞げない)。地図内のピンチズームはLeaflet処理なので生きている。入力欄は16pxに統一(iOSのフォーカス時自動ズーム対策)
- **リアクション(2026-08-23)**: 魚と各記録に👍❤️🤩📸🤿の5種をタップでオン/オフ。同じ人は同じ対象に各1回まで(端末トークンで判定・取り消しは自分の分だけ)。図鑑カードに合計数を表示。**要サーバーv5**(reactionsシートは初回リアクション時に自動作成)
- **ダイビングログ(2026-08-23)**: 下部タブ「ログ」。1本=通算No/日付/ポイント/潜水時間/最大水深/水温/透明度/天気/バディ/メモ(必須は日付+ポイント)。編集は本人+オーナー。「自分のログだけ」絞り込み・ログへのリアクション可。**図鑑との紐づけは「名前×日付×ポイント」一致の自動導出**(ログ詳細に図鑑投稿が並び、魚の記録から「この日のログ」へ飛べる)。通算No.は自分の過去ログ+1を自動提案(初回は手入力=既存本数持ちに対応)。**要サーバーv6**(logsシート自動作成)
- **重複対策3点セット(2026-09-02・v11)**: ①送信の冪等化=clientKey(ラグで再送しても記録/ログは1件しか保存されない・根本対策) ②同名の魚は登録時に自動統合(新規行を作らず既存に合流・見られるポイントは和集合) ③削除=魚(登録者本人+オーナー。本人は他人の記録/コメントが付いていると不可)と記録(本人+オーナー)。削除は編集画面の赤ボタンから。写真はDriveゴミ箱行き(30日復元可)
- **撮影者名と登録者名の分離(2026-08-24・v10)**: 記録に「撮影者名」欄(自由入力・空欄なら登録者=自分)。クレジットの優先順位=①「表示しない」チェック(撮影者なし表記) > ②撮影者名 > ③登録者名。記録行には登録者を表示し、撮影者が別人なら「・撮影: ○○」を併記。編集権限とログ紐づけは従来どおり登録者(トークン)基準
- **代表写真のピン留め(2026-08-24・v9)**: カルーセルの各写真に「代表にする」ボタン(全員可・魚情報の共同編集と同方針)。ピン留めした写真がカードの顔とカルーセル先頭になる(解除すると既定=観察日が新しい記録の1枚目に戻る)。写真クレジットは「撮影者なし」表記に対応(投稿/編集のチェックボックス)
- **サーバー更新(v4)が必要**: `?action=ping` の `ver` で判定。**v4はv3の重大バグ修正を含む**(appendRowが実シートのヘッダー順を無視して書くため、v3で新規の魚を登録すると列がズレ、識別トークンが公開JSONに露出し得た。実データは全行検査済みで被害なし=v3稼働中に新規の魚登録が無かった)。v3のまま運用しない
